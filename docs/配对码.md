# 短配对码 · 离线局域网连接方案

> 状态：**设计讨论稿**（待评审后进入 `plan.md` / 实现）  
> 背景：跨网段、无外网、无摄像头场景下，「复制 IP」「二维码」均不合适；需 **键盘输入 6 位数字** 完成首次配对。  
> 关联：`docs/02_技术实现建议.md` §13.6 · `docs/03_数据模型与协议草案.md` §6.2 · `docs/飞鸽飞秋.md` §6.1 A5

---

## 1. 要解决的问题

| 现状 | 用户痛点 |
|------|----------|
| 同网段 UDP 自动发现（`43123`） | ✅ 零配置；**主路径，继续保留** |
| 跨网段手动 `IP:43124` | 能连，但要记 IP、找隐藏菜单 |
| 复制地址 | 离线两台桌面机之间 **无法传递剪贴板** |
| 二维码 | 很多机器 **没有摄像头**（服务器、工控机、台式机） |

**目标**：在 **不依赖互联网、不依赖摄像头** 的前提下，让普通用户用 **6 位数字 + 键盘** 完成「第一次连上同事」，之后自动记住（种子 / P2P 重连）。

---

## 2. 设计原则

| 原则 | 说明 |
|------|------|
| **数据不出域** | 不配公网配对服务；全程 UDP/TCP 局域网 |
| **无中心服务器** | 配对状态仅在「发起方本机」内存 + 短时广播；不做账号云 |
| **先同网段、后跨网段** | 同网段：只输入码；跨网段：允许加「可选尾码 / 路由探测」 |
| **一次配对，长期有效** | 成功后写入发现种子 + TCP 对端缓存（已有 `connectDiscoverSeeds`） |
| **短码可读** | 6 位十进制，分组显示 `847 293`，避免 0/O、1/l 歧义（纯数字） |

### 非目标（本期不做）

- 公网中继、短信验证码、扫码
- 替代群组 `autoDiscover` 语义（配对只解决 **节点可达**，不自动加群）
- 强制替换现有 `host:port` 手动输入（保留高级入口）

## 3. 用户故事

### 3.1 同一交换机 / 同一 WiFi（同网段，无外网）

```
同事 A：发现 → 「让同事加入我」→ 屏幕显示  847 293  （5 分钟有效）
同事 B：发现 → 「加入同事」→ 输入 847293 → 连接成功 → 看到 A 的人/群
```

无需 IP、摄像头、互联网。

### 3.2 跨网段（如 192.168.30.x ↔ 192.168.20.x，路由可达）

```
A（20.109）显示：配对码 847 293 · 地址 192.168.20.109
B（30.170）：
  方案甲（推荐）：输入 847293 → 客户端按本机路由表对「可达网段」发配对查询（见 §5.3）
  方案乙（兜底）：输入 847293 + 选择「我知道对方网段」→ 填 20.109（IP 仅 4 段数字，比记端口简单）
```

配对成功后写入种子，**下次开机自动连**，不再输入。

### 3.3 机房 / 无屏服务器

- A 通过 SSH 执行 `lanpm pairing start`（CLI，后期）打印码  
- B 桌面端输入码 + 服务器 IP（尾段）  
- 或 U 盘导出配对包（与短码 **并列** 的 P2 能力，见 §8）

## 4. 交互设计（草案）

### 4.1 入口合并

**发现** 面板顶部改为两个主按钮（取代散落的「手动添加节点」「种子」）：

| 按钮 | 角色 | 行为 |
|------|------|------|
| **让同事加入我** | 发起方 | 进入「等待配对」屏 |
| **加入同事** | 加入方 | 6 位输入框 + 连接 |

高级：展开「手动输入 IP:端口」「管理种子」「导出/导入配对文件」。

### 4.2 发起方界面

```
┌─────────────────────────────────────┐
│  让同事加入我                        │
│                                     │
│         8 4 7   2 9 3               │  ← 大号等宽字体
│                                     │
│  5:00 后失效 · 本机 192.168.20.109   │  ← 小字，跨网段时参考
│                                     │
│  [ 复制配对信息 ]  [ 取消 ]          │  ← 复制给有 IM 的场景，非主路径
└─────────────────────────────────────┘
```

- 配对进行中：UDP `pairing_offer` + TCP 监听 `pairing_resolve`
- 有人连上：Toast「某某 已连接」+ 可选「信任此设备」

### 4.3 加入方界面

```
┌─────────────────────────────────────┐
│  加入同事                            │
│                                     │
│  配对码  [ 8 ][ 4 ][ 7 ][ 2 ][ 9 ][ 3 ] │
│                                     │
│  ☐ 对方和我不在同一 WiFi（跨网段）    │  ← 勾选后显示可选 IP
│     对方 IP  [ 192.168.20.109    ]   │
│                                     │
│            [ 连接 ]                  │
└─────────────────────────────────────┘
```

- 默认同网段：只填码  
- 跨网段：勾选 + IP（或仅填 IP **最后一段** `109`，客户端补全网段候选，见 §5.3）

### 4.4 与现有能力关系

| 现有 | 配对码之后 |
|------|------------|
| UDP 自动发现 | 保留；同网段仍优先自动 |
| 手动 `IP:43124` | 收进「高级」 |
| 发现种子 | 配对成功 **自动 add seed** |
| TCP 握手带群组（1.41.4+） | 配对连上后走同一套 `registerTcpPeer` |

## 5. 技术方案（无中心）

### 5.1 配对会话（发起方）

发起「让同事加入我」时：

1. 生成 `pairingId`（uuid）、`code`（6 位数字，`100000–999999` 或 `000000–999999` 补零显示）
2. `expiresAt = now + 5min`（可配置）
3. 内存表：`activePairing: { code, pairingId, expiresAt, attempts }`
4. 启动定时器：每 **2s** 发送 `pairing_offer`（UDP），直到过期或取消
5. TCP `43124` 接受 `pairing_resolve`（明文 wire，在 DH 握手之前）

**安全**：短码 + 短时效 + 发起方可选「需确认」；不替代群组密钥与消息加密。

### 5.2 UDP 报文（扩展 discovery 通道，`43123`）

与现有 `{ v:1, kind:'discovery', payload }` 并列：

```typescript
// 发起方周期广播
interface PairingOfferPacket {
  v: 1
  kind: 'pairing_offer'
  code: string              // "847293"
  pairingId: string
  deviceId: string
  userId: string
  displayName: string
  listenPort: number        // 默认 43124
  host?: string             // 源 IP
  expiresAt: string         // ISO8601
}

// 加入方查询（广播或单播）
interface PairingLookupPacket {
  v: 1
  kind: 'pairing_lookup'
  code: string
  joinerDeviceId: string
  joinerDisplayName: string
}

// 发起方单播回复（仅当 code 匹配且未过期）
interface PairingFoundPacket {
  v: 1
  kind: 'pairing_found'
  pairingId: string
  deviceId: string
  userId: string
  displayName: string
  listenPort: number
  host: string
}
```

**同网段流程**：B 输入码 → B 广播 `pairing_lookup` → A 回复 `pairing_found` → B `connectManualHost(host, port)` → 现有 TCP 握手。

### 5.3 跨网段：配对查询怎么找到 A？

UDP 广播 **不过路由器**，仅同网段有效。跨网段采用 **分层策略**（由易到难，可分期）：

| 阶段 | 策略 | 说明 |
|------|------|------|
| **P0** | 用户勾选跨网段 + 输入 **完整 IP** | 码用于 **校验连对机器**（防连错），非自动发现 |
| **P1** | **路由表引导单播**：对本机 `route` 中「直连网段」各发 `pairing_lookup` 到子网广播地址 | 覆盖「大局域网多网段、路由可达」 |
| **P2** | 可选「网段扫描」：对指定 `/24` 发 `pairing_lookup` 到 `.1–.254:43123` | 慢、可关；仅高级模式 |

**推荐产品默认**：P0（码 + 可选 IP）即可解决当前 **30.x ↔ 20.x** 场景——用户只需看 A 屏幕上的 `192.168.20.109`，比记 `IP:43124` 少记端口；码保证没连错人。

**IP 尾段简化（可选 UX）**：

- A 显示 `109` 为「地址尾码」
- B 勾选跨网段，只输入 `847293` 和 `109`
- B 客户端根据本机已知种子 / 历史 / 路由表构造候选：`192.168.20.109`、`192.168.30.109`… 逐个 `pairing_lookup` 单播

### 5.4 TCP `pairing_resolve`（兜底）

UDP 被防火墙拦时，加入方对 **已知 IP** 的 `43124` 发送 wire 消息（与 `handshake` 同级，未加密）：

```typescript
| { kind: 'pairing_resolve'; code: string; joinerDeviceId: string; joinerDisplayName: string }
| { kind: 'pairing_resolve_ok'; ...WirePeerProfile }
| { kind: 'pairing_resolve_fail'; reason: 'expired' | 'mismatch' | 'rate_limit' }
```

成功后走现有 `connectManualHost` / 握手逻辑。

### 5.5 配对成功后的持久化

1. `addDiscoverSeed(`${host}:${listenPort}`)` — 已有 API  
2. `connectManualPeer` 立即执行  
3. （可选）`sync_meta` 记录最近配对设备昵称，发现页「最近协作设备」

## 6. 安全与滥用

| 风险 | 对策 |
|------|------|
| 6 位码被猜中 | 5 分钟 TTL；每分钟限流；失败 5 次锁定该码；可选发起方点选确认 |
| 局域网嗅探 | 配对只暴露 **可达性 + 身份**；业务仍走 DH + AES（现有） |
| 重放 | `pairingId` 一次性；`pairing_found` 后作废 |
| 骚扰连接 | 发起方可随时「取消配对」；关闭配对窗口即停播 |

**信任模型**：与飞鸽一致——**首次局域网信任**；企业若要零信任，靠后续「需确认」开关。

## 8. 与「U 盘配对文件」并列（P2）

完全无屏 / 空气隔离场景：

```json
{
  "v": 1,
  "host": "192.168.20.109",
  "port": 43124,
  "deviceId": "...",
  "displayName": "ubuntu-lanpm",
  "fingerprint": "sha256(...)"
}
```

B 端「导入配对文件」→ 等同种子 + 首次 TCP。与短码 **互补**，不互斥。

## 9. 开放问题（评审时请拍板）

1. **码长度**：6 位固定 vs 4 位更易记但更易撞？  
2. **跨网段默认**：是否强制显示 IP（诚实） vs 仅显示码（简单但可能连不上）？  
   - **建议**：同网段只显示码；跨网段 **同时显示码 + IP**，文案说明「不在同一 WiFi 时请告诉对方 IP 尾段」。  
3. **配对是否自动加群**：否；仍走发现里「加入群组」。  
4. **匿名群**：配对只建立节点，与群类型无关。  
5. **多网卡**：`pairing_offer` 从所有 LAN 接口各发一份（与 UDP discovery 一致）。

## 10. 和「完全没有局域网」的边界

短配对码 **不能** 替代物理组网：

- 两台机器必须先 **同一二层/三层可达**（交换机、热点、路由）。  
- **没有网线的两台孤机** → 请先接交换机或开热点，再谈配对码。

产品 Setup 可增加一步图示：

> 「请把要协作的电脑接到 **同一个路由器或交换机**（不需要上网）」

## 11. 小结

| 问题 | 答案 |
|------|------|
| 离线、无摄像头能连吗？ | **能**——同网段只输入 6 位码；跨网段码 + IP/尾段 |
| 比记 `IP:43124` 好在哪？ | 用户只记 **数字**；端口与种子 **自动**；码可防连错机器 |
| 还要自动发现吗？ | **要**；同网段仍零配置，配对码是 **跨网段/首次** 的降级友好路径 |
