### 13.2 发现机制


| 方式    | 协议     | 说明                      |
| ----- | ------ | ----------------------- |
| 局域网广播 | UDP    | 自动发现同网段节点与 `autoDiscover` 群组（端口 `43123`） |
| **群组连接码** | UDP + TCP | 6 位码打通发现目录；跨网段 IP/尾段/路由引导；详见 §13.7 |
| 手动添加  | TCP/IP | 输入 `host:port` 主动建链（VPN / UDP 不可达）；**已实现**，入口在发现页高级区，详见 §13.6 |
| 发现中继 | TCP `discover_relay` | 已连对端互推 peers/groups/seeds，`hop`≤2；详见 §13.7 |
| 组播发现  | UDP 组播 | 跨子网发现（候选）                   |


### 13.3 数据同步


| 数据类型  | 同步策略        | 冲突解决        |
| ----- | ----------- | ----------- |
| 聊天消息  | 广播 + 顺序保证   | Lamport 时间戳 |
| 任务数据  | CRDT (Yjs)  | 自动合并        |
| 文件元数据 | 索引广播 + 按需拉取 | 最后写入获胜      |
| 成员状态  | 心跳广播        | 最新心跳为准      |

#### 同用户多设备与已读策略（补充）

- 用户在线态按 `userId` 聚合：任一设备在线即用户在线。
- 消息已读按 `userId` 聚合：任一设备已读即用户已读。
- 冲突统一采用“最新事件优先”（LWW），仅影响当前用户本人状态，不回滚他人状态。

### 13.5 网络协议参数初稿（可落地默认值）

> 该初稿用于先行开发联调，后续可根据实测调优。

| 项目 | 默认值 | 说明 |
|------|--------|------|
| UDP 广播端口 | `43123` | 局域网节点发现固定端口 |
| UDP 组播地址 | `239.255.43.123` | 与发现端口共用；跨子网（**ARCH-03**） |
| UDP 广播间隔 | `3s` | 周期广播本机节点信息 |
| 心跳间隔 | `5s` | 在线状态同步频率 |
| 离线判定超时 | `15s` | 连续 3 个心跳周期未收到视为离线 |
| 节点信息 TTL | `30s` | 发现缓存过期时间 |
| 文件传输并发 | `3` | 与产品需求保持一致 |
| 单分片大小 | `256KB` | 大文件分片传输默认块 |
| 重试策略 | 指数退避（1s/2s/4s，上限 20s） | 避免雪崩重连 |
| 群组密钥轮换 | `24h` | 群组广播密钥定期更新 |
| 会话密钥轮换 | 每次重连 | 降低长连接密钥暴露风险 |

### 13.6 手动添加节点（ARCH-02）

**手动连接 P2P 对端（peer）**，非任务树节点、非虚拟服务器。

| 术语 | 含义 |
|------|------|
| **节点（peer）** | 局域网或 VPN 内另一台运行 LanPM 的设备实例 |
| **自动发现** | UDP 广播端口 `43123`（§13.5） |
| **手动添加** | 输入对端 `host:port` 主动建链（默认 TCP `43124`） |

**UI（v1.55+）**：顶栏网络圆点下拉 **仅**「刷新状态」「重连」；**不再**含「添加节点」。手动对端由 **发现面板** 健康区 CTA「无法发现？连接对端」或高级区打开 `ManualPeerModal`（`host:port`，如 `192.168.1.10:43124`）。实现：`TopBar.tsx` · `DiscoverModal.tsx` · `ManualPeerModal.tsx`。

**地址格式**（`parseHostPort`，`@shared/network/manualPeer`）：`主机:端口`，端口 1–65535；勿带 `http://` 前缀。

**调用链**：`networkStore.connectManualPeer` → IPC `network:connectManualPeer` → `RealNetworkTransport.connectManualHost`（真网）或 `NetworkStub.registerManualPeer`（Stub 写入 `.lanpm/stub-bus/peers/manual-*.json`，可用 `LANPM_STUB_BUS_DIR`）。

**适用**：VPN、UDP 发现被防火墙屏蔽、已知对端 IP。手验见 [05_测试与联调发布.md](./05_测试与联调发布.md) §3.4、§6.2。

**排错**：格式错误 → `host:port`；连接失败 → 对端在线、防火墙放行 TCP `43124`；Stub 仅登记 peer 文件不代表真网消息互通。

### 13.7 群组连接码配对（v1.42+ ✅）

离线局域网用 **6 位数字连接码** 打通 **发现目录**（可见群 ≠ 自动入群）。产品叙事见 [01](./01_产品需求文档.md) §11.4；报文见 [03](./03_数据模型与协议草案.md) §6.5。

#### 13.7.1 配对会话（发起方）

1. 生成 `pairingId`（uuid）、`code`（6 位，`100000–999999`）
2. `expiresAt = now + 5min`（`PAIRING_TTL_MS`）
3. 内存表 `activePairing`；每 **2s** UDP `pairing_offer`；TCP `43124` 接受 `pairing_resolve`（DH 握手前明文）
4. 取消或过期即停播；`pairingId` **一次性**

常量与类型：`src/shared/network/pairingTypes.ts`（`MAX_PAIRING_FAIL_PER_JOINER=5` · `MAX_PAIRING_LOOKUPS_PER_JOINER_PER_MINUTE=12`）。

#### 13.7.2 同网段流程

B 输入码 → B 广播 `pairing_lookup` → A 回复 `pairing_found` → B `connectManualHost(host, port)` → 现有 TCP 握手 + `peer_advert`。

#### 13.7.3 跨网段策略

| 阶段 | 策略 | 版本 |
|------|------|------|
| P0 | 用户勾选跨网段 + **完整 IP** 或 **尾段**（如 `109`） | v1.42 |
| P1 | **路由表引导单播**：`route print` / `ip route` / **macOS** `netstat -rn` → 各子网 `.255` 并行 `pairing_lookup` | v1.43 |
| P2 | 可选 **网段扫描**（P2）：对可达 `/24` 分批 `pairing_lookup` `.1–.254`（慢，默认关；`subnetScan` 高级开关） | v1.46 |

实现：`pairingHostResolve` · `routeGuidedResolve` · `subnetScanHosts` · `joinWithPairingCode` 多候选循环。

#### 13.7.4 TCP 兜底

UDP 被拦时，对已知 IP 的 `43124` 发 `pairing_resolve` → `pairing_resolve_ok`（`WirePeerProfile`）或 `pairing_resolve_fail`（`expired` \| `mismatch` \| `rate_limit`）。实现：`peerLink.ts` · `wireProtocol.ts`。

#### 13.7.5 配对成功后

1. `addDiscoverSeed(\`${host}:${listenPort}\`)`  
2. 立即 `connectManualPeer`  
3. 可选：`sync_meta` 记录最近协作设备

#### 13.7.6 发现中继 `discover_relay`

已 TCP 连接的节点周期性互推本机合并后的发现目录（明文目录，无业务密文）：

- 包体：`hop` · `viaDeviceId` · `peers[]` · `groups[]` · `seeds?[]`
- 规则：`peer_advert` 后 / 周期（约 30s）；合并 `discoverGroupRegistry`、peer 列表、种子；`hop` 为 0 不再转发；上限 **2**
- 实现：`src/shared/discover/discoverRelay.ts` · `RealNetworkTransport`

#### 13.7.7 入群治理

| 路径 | 报文 / 存储 | 行为 |
|------|-------------|------|
| 申请加入 | `join_request` / `join_request_decision` · `group_join_requests` 表 | 群主审批 |
| 群邀请码 | UDP `group_invite_offer/lookup/found` | 输入码 **直接入群** |

#### 13.7.8 U 盘配对文件与 CLI（v1.44+）

`lanpm-peer.json` v1：`host` · `port` · `deviceId` · `displayName` · `fingerprint`（SHA-256）。GUI 导入/导出；CLI `lanpm pairing start` \| `join`。

#### 13.7.9 实现与验收对照

| 能力 | 实现 | 验收 |
|------|------|------|
| UDP `pairing_offer/lookup/found` | `PairingSessionHost` · `PairingUdpController` | `verify:pairing-udp` |
| TCP `pairing_resolve` 兜底 | `PeerLink.connectHostWithPairing` | `verify:pairing-tcp` |
| 跨网段 IP/尾段 | `pairingHostResolve` · `joinWithPairingCode` | `verify:pairing-cross-subnet` |
| 路由表引导单播 | `routeTable` · `routeGuidedResolve` | `verify:pairing-route` |
| `/24` 网段扫描（P2） | `subnetScanHosts` · `lookupPairingCodeBatched` | `verify:pairing-subnet-scan` |
| U 盘配对文件 | `peerFile` · `peerFileService` | `verify:pairing-peer` |
| CLI 配对 | `scripts/lanpm.mjs` | `verify:pairing-cli` |
| TTL · 限流 · 一次性 `pairingId` | `pairingTypes` · `PairingSessionHost` | `verify:pairing-security` |
| 发现中继 `discover_relay` | TCP 对端互推 · `hop`≤2 | `verify:discover-relay` |

### 14.1 性能要求


| 指标         | 要求           |

### 14.2 兼容性


| 平台      | 最低版本                       |
| ------- | -------------------------- |
| Windows | 10 (64-bit)                |

### 14.3 可靠性


| 指标   | 目标           |
| ---- | ------------ |
| 离线消息 | 上线后自动同步（7天内） |
| 数据备份 | 支持导出/导入全量数据  |
| 崩溃恢复 | 重启后恢复上次会话    |


### 14.4 安全性


| 维度   | 方案                    |
| ---- | --------------------- |
| 传输加密 | UDP 发现 + WebRTC DataChannel；应用层 DH + AES-256-GCM + HMAC-SHA256（无独立 TLS 层） |
| 本地存储 | SQLite 加密（SQLCipher）  |
| 身份验证 | 首次使用无密码，信任局域网环境       |
| 防篡改  | 消息哈希链（可选）             |

## 15. AI 联网扩展（可选 · v1.33+）

> 产品原则与入口见 [01](./01_产品需求文档.md) §12.3–§12.4；数据模型见 [03](./03_数据模型与协议草案.md) §3.6–§3.7；UI 见 [04](./04_交互与UI约定.md) §4.2。  
> **一句话**：协作数据在 LAN；AI 为 **可选联网扩展**，Key 仅主进程、会话 **不进** P2P。

### 15.1 进程与调用链

```text
Renderer                          Main (Electron)
────────                          ───────────────
AiAssistantShell                  aiConfigService · aiThreadService
  MarkdownView / Composer    ←→   cockpitService.callExternalAi / streamChat
CockpitView · TaskDetail          aiSubtaskService · aiPatrolService · aiPipelineRunner
IPC: AI_IPC（channels.ts）        Key 解密仅 main · 脱敏 assemblePrompt
  ← ai:streamChunk/Done/Error     OpenAI-compatible POST {baseUrl}/chat/completions
```

外呼 **仅在主进程**；`dev:web` Stub 为 mock，验收以 Electron 为准。

### 15.2 配置与门禁

| 项 | 实现 |
|----|------|
| 存储 | `ai_config` 表 · `getAiConfig` / `saveAiConfig` |
| 厂商 | `AI_PROVIDER_PRESETS`（DeepSeek / 通义 / 智谱 / Moonshot / OpenAI / Anthropic / custom） |
| 门禁 | `getAiGateStatus`：`enabled` · `hasApiKey` · `online` · `endpointReachable` |
| 端点探测 | `GET {baseUrl}/models` · TTL 成功 5min / 失败 2min · `ai:probeEndpoint` |
| 脱敏 | `dataPolicy: desensitized-only` · `AiTaskAuditPayload` · 隐式上下文分层（系统/场景/对象，见 `aiContextService`） |

### 15.3 IPC 面（`AI_IPC`）

| 通道 | 用途 |
|------|------|
| `streamChat` | 流式多轮（分片 `ai:streamChunk`） |
| `reviewTask` | 单任务结构化评审 |
| `proposeSubtasks` / `confirmSubtasks` | 拆分子任务草案 → 人审落库 |
| `shareToChat` | 报告/回复发到当前群（`meta.source: ai-assistant`） |
| `listThreads` … `deleteThread` | 本机 `ai_threads` / `ai_messages` |
| `startPipeline` / `resumePipeline` / `cancelPipeline` | L3 流水线 |
| `listPatrolRuns` / `getLatestPatrolRun` | 定时巡检记录 |

### 15.4 L3 流水线（自建轻量状态机 · SPRINT-AI-05）

**不**默认引入 LangGraph.js / open-multi-agent 进核心依赖。

| Preset | 说明 | 验收 |
|--------|------|------|
| `healthCheck`（L3a） | 群概况 → LLM 风险摘要 → Top3 `reviewTask` → Markdown；**只读** | `verify:ai-pipeline` |
| `taskRemediate`（L3b） | `gatherContext` → `proposeSubtasks`（`awaiting_confirm`）→ 人审 `confirmSubtasks` → 报告 | `verify:ai-pipeline-human` |

持久化：`ai_pipeline_runs` · `steps_json` 含 `pendingConfirm` / `createdTaskIds`。

### 15.5 定时巡检（SPRINT-AI-03）

`aiPatrolService` + `aiPatrolScheduler`（默认 24h · 启动延迟 5min）· `ai_patrol_runs` · 桌面通知 · 驾驶舱/助手续读。

### 15.6 插件

`plugins/lanpm.ai-assistant` — **builtin** · `pricing: free`；与核心顶栏入口同哲学，不要求用户单独安装。

### 15.7 开源选型（MIT 优先）

| 层 | 依赖 | 角色 |
|----|------|------|
| 流式 | Vercel `ai` SDK | 主进程 `streamText` / `generateObject` |
| Markdown | `react-markdown` + GFM | `MarkdownView`（助手 + 群聊启发式） |
| 结构化 | Zod | `subtaskSchemas` · pipeline 输出 |

详表增量见 [MIT开源替代.md](./MIT开源替代.md) §4.6。

### 15.8 L3 编排调研结论（SPRINT-AI-05）

首条 L3 采用 **自建轻量状态机**（`aiPipelineRunner`）+ 复用 L2 步骤，**不**默认引入 LangGraph.js / open-multi-agent。验收：`verify:ai-orchestration-spike`。

### 15.9 L3b 人审写库流水线（SPRINT-AI-07 · v1.41.0）

| 能力 | 实现 |
|------|------|
| 状态 | `awaiting_confirm` · 写库前暂停 |
| IPC | `ai:resumePipeline` · `ai:cancelPipeline` |
| Preset | `taskRemediate`：`proposeSubtasks`（`requiresHumanConfirm`）→ `SubtaskPreviewModal` → `confirmSubtasks` |
| UI | 驾驶舱需关注任务「补救拆分」· 助手 preset `taskRemediate` |

## 18. 技术实现建议

### 18.1 项目结构

```
lanpm/
├── src/
│   ├── main/           # Electron 主进程
│   │   ├── index.ts
│   │   ├── network/    # UDP 发现 + P2P 连接
│   │   ├── storage/    # SQLite + IndexedDB
│   │   └── crypto/     # 加密模块
│   ├── renderer/       # 渲染进程（前端）
│   │   ├── views/      # 5 个主视图
│   │   ├── components/ # 公共组件
│   │   ├── stores/     # Zustand 状态
│   │   └── styles/     # 主题样式
│   └── preload/        # 预加载脚本
├── resources/          # 图标、安装包资源
├── docs/               # 文档
├── tests/              # unit/ · static/ · integration/ · runners/
├── package.json
└── electron-builder.yml
```

### 18.2 推荐依赖

```json
{
  "dependencies": {
    "electron": "^28.0.0",
```

> 渲染层样式采用 **CSS Modules**；主题通过 Ant Design `ConfigProvider` + Design Token 切换亮/暗色。

### 18.3 关键实现难点


| 难点          | 解决方案                                      |
| ----------- | ----------------------------------------- |
| UDP 跨平台广播   | Electron 主进程中使用 `dgram` 模块                |
| P2P 穿透      | `simple-peer` + STUN 服务器（可选）              |
| CRDT 同步     | Yjs + WebRTC 数据通道                         |
| Office 文件预览 | 主链路采用 LibreOffice 本地转换（不出域）                |
| 多设备合并       | 心跳机制 + 状态聚合                               |
| 甘特图          | `gantt-task-react` + Ant Design 工具栏/布局       |
| 看板拖拽        | `@dnd-kit/core`（M3，见 `docs/04` §8）           |
