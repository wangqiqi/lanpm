### 磁盘路径约定（防撑爆）

| 用途 | 路径 | 可否清 |
|------|------|--------|
| 构建输出 | 仓库 `out/` · `dist/` · `coverage/` | 可删，下次 `build`/测再生 |
| 测试临时库/截图 userData | 仓库 **`.lanpm/tmp/`**（`tests/lanpmTemp.ts`） | 测完应自动删；残留可 `rm -rf .lanpm/tmp` |
| Stub 文件总线 | 仓库 **`.lanpm/stub-bus/`**（可用 `LANPM_STUB_BUS_DIR` 覆盖） | 可清；联调前可空目录 |
| 视觉截图产物（临时） | 仓库 `.lanpm/visual-screenshots/` | 可清 |
| 截图基线（入库） | `docs/screenshots/baselines/` | `screenshots:capture` 更新 |
| 双实例手验 userData | 仓库 **`.lanpm/dev-a/`** · **`.lanpm/dev-b/`** | 可清；见 §3.1 |
| 应用持久数据 | `app.getPath('userData')`（Linux 常为 `~/.config/lanpm`） | **勿当缓存清** |
| Electron 二进制缓存 | `~/.cache/electron` · `~/.cache/electron-builder` | 可清（可重建；`./onekey_run.sh clean deep` 会清） |

**原则**：持久数据 → 稳定目录（userData）；可重建工具链 → `~/.cache`；连续自动化/手验 → **仓库内 `.lanpm/`**，禁止默认堆 `/tmp/lanpm-*`。一键清理：`./onekey_run.sh clean`（产物）· `clean deep`（含 `node_modules` + Electron 缓存）。

#### 1.2.3 VirtualLan 故障注入（`verify:discover-sim-full` 后缀）

`VirtualLanBus` 支持 `udpDropRate`（0–1）与 `udpDelayMs`；`tests/integration/discover-sim/fault-scenarios.ts`：

| 场景 | 断言 |
|------|------|
| `tcp-only-fallback` | joiner `disableUdp` → `pairing_resolve` TCP 成功 |
| `udp-blackhole` | `udpDropRate:1` → lookup 超时 |
| `pairing-rate-limit` | 超额错误码 lookup → `rate_limit` |

### 1.3 CI / 本地发布前

```bash
npm run verify:release-gate   # 推荐：含 docs-code、visual、discover、pairing-code、project、m7
# 配对/发现单跑：
npm run verify:pairing-code
# 或分步：
npm run verify:project && npm run verify:m7
npm run build && xvfb-run -a npm run verify:visual-screenshots
```

CI：

| Workflow | 触发 | 用途 |
|----------|------|------|
| `verify.yml` | push/PR `master`·`main`·`develop` · **Run workflow** | 三平台 `verify:m7`（日常 PR 门禁；**不含** pairing-code） |
| `release.yml` | **Run workflow**（tag + ref=master）· push `v*` | 三平台包 → **CI 自动 Publish**（含 deb） |
| `sync-r2.yml` | `Release` 成功 · **Run workflow** | **可选** R2 独立下载页；未配置 `R2_*`/`BASE_URL` Variables 时跳过 |

**发版 / PR 配对门禁**：本地与 tag 发版前须 `npm run verify:release-gate`（含 `verify:pairing-code`）。日常 CI `verify.yml` 仍只跑 `verify:m7`；合并前维护者应在本地或发版流水线确认 pairing 全绿。

## 5. 性能测量（M7）

可重复入口（**不是** electron-builder 安装包双击）：

```bash
npm run build
npm run measure:perf -- --quick          # CI 友好；idle 短等，非 §5 内存预算
npm run measure:perf -- --full           # 冷启动 ×3 · idle 60s · Tab ×10
npm run verify:measure-perf              # 脚本/JSON 契约守卫
npm run verify:m7-perf                   # Node 侧 schema/加密信封/消息页冒烟
```

JSON 写入 gitignore 的 `.lanpm/perf/latest.json`；隔离 `userData` 在 `.lanpm/tmp/lanpm-perf-*`。Linux 开发/测量进程**默认关 GPU**（无 Vulkan 会 Electron FATAL）。有独显要对照 RSS 时：

```bash
npm run measure:perf -- --quick
LANPM_ENABLE_GPU=1 npm run measure:perf -- --quick
```

对比两份 JSON 的 `rssIdleMb` / `rssChat100Mb` 与 `notes.gpu`（default-off vs opt-in）。无独显/CI **不要**设 `LANPM_ENABLE_GPU=1`。E2E 与 `tests/integration/electron-smoke-app.mjs` 仍强制关 GPU。**SPRINT-50** 本机 Linux `--quick`：opt-in **未**降低 RSS（见 [06 §4](./06_ROADMAP.md) #8）；仍默认关 GPU，**不对标** §5.2 200MB。`measure:perf` Tab 切片只点默认底栏 chat / board / tree。

### 5.1 冷启动 ≤ 3s

**安装包手测**：双击图标 → 底栏 Tab 可点；SSD；各平台 3 次中位数。

**本机脚本**：`measure:perf --cold`（`--full` 为 3 次）测 `out/main/index.js` + Electron，字段 `coldStartMs.median`。

### 5.2 内存

| 场景 | 指标 |
|------|------|
| 空闲 60s | ≤ 200MB |
| 聊天 100 条 | ≤ 350MB |

`--full` 才按 60s idle 对齐上表；`--quick` 的 `rssIdleMb` 须视为非预算。脚本记 Linux 进程树 RSS（`rssIdleMb` / `rssChat100Mb`）。

Linux 默认关硬件加速时 RSS 常高于上表，**不以默认进程对标 200MB**。有独显可用上一节 `LANPM_ENABLE_GPU=1` 对照，仍不承诺达到预算。

### 5.3 UI P95 ≤ 100ms

切换 5 个底部 Tab、发一条消息；各 10 次取 P95（开发模式可放宽 150ms 并注明）。

脚本：`measure:perf --tabs` → `tabSwitchP95Ms`（`--quick` 每 Tab 2 轮，`--full` 10 轮）。`--quick` P95 含已加载模块；**首次**切看板/树/文件/甘特/日历/白板会走 `lazy()` 分包（驾驶舱 `/cockpit` 同理），勿与二次切换混读。

实现侧（SPRINT-30）：驾驶舱仪表盘一次 JOIN 取项目任务+部门，不再按群 `listTasksByGroup` × `getUserById`；文件 `file_chunk` 进度 `broadcastFiles` 节流 100ms，末包 `done` / 失败 / 完成仍立即推送。协议仍 Base64。Linux 关 GPU 时 RSS 仍可能远高于 §5.2 表，不以本轮优化对标 200MB。

实现侧（SPRINT-31）：`probeSqliteAtRest` 只读 16 字节文件头（大库启动不再整文件读入）；任务 `create`/`update`/`move`/聊天建任务 成功后本地 upsert，不再 `listTasks` 整群。删除级联/上浮与依赖边仍整群刷新。守卫：`verify:task-store-patch`（含在 `verify:p0`）。

### 5.4 明文 vs SQLCipher

`measure:perf --db` → `dbPlainMs` / `dbCipherMs`（`listRecentMessagesPage` P95）。不替代 `verify:m7-perf`。

## 6. 局域网真网联调（M6）

### 6.0 证据边界（对外怎么讲）

| 层级 | 命令 / 文档 | 证明什么 | 不证明什么 |
|------|-------------|----------|------------|
| 自动化 | `npm run verify:m6` | 本机 **loopback**：DH + 密封信封 + `RealNetworkTransport` 回环冒烟 | **不是**两台电脑、不是交换机/防火墙、不是 10MB 真传 |
| Stub 双实例 | [§3](#3-networkstub-联调m2) `npm run dev -- --user-data-dir=.lanpm/dev-*` | 文件总线互见消息 | **不是** UDP/TCP 真网 |
| 真双机手验 | 下列 §6.1–§6.2 | 发现 → 加群/私聊/文件/断线（人工勾选） | CI **未**跑；[06_ROADMAP](./06_ROADMAP.md) §4 仍标延期，直至有人填本表 |

发版可以说：协议与 loopback 有自动化；**不能**说「CI 已验证局域网双机」。无实测记录时不要把 §6.2 勾成已交付。

### 6.1 环境（真双机 · 人工）

- **两台设备**（或两台虚拟机），同网段或 VPN 互通；每台只跑 **一个** LanPM 进程（单实例锁 + TCP `43124`）。
- 默认 `LANPM_NETWORK` 未设时走 **real**（`resolveNetworkMode`）。勿在真网手验时设 `LANPM_NETWORK=stub`。
- 防火墙放行 **UDP `43123`**（发现）与 **TCP `43124`**（P2P / 手动节点）。详见 [02](./02_技术实现建议.md) §13.5。
- 启动：各机 `npm run dev` 或安装包；不同 `userData`（各机自己的配置目录即可）。

### 6.2 步骤（手验清单 · 未勾选 ≠ 已测）

| # | 操作 | 预期 |
|---|------|------|
| 1 | 启动等待 3–15s | UDP 发现对端 |
| 2 | A 发消息 | B 加密收到 |
| 3 | A 上传 10MB | B 下载 SHA256 一致 |
| 4 | 同用户双设备 | 在线态合并 |
| 5 | A 断网 20s 恢复 | 自动重连、离线补同步 |
| 6 | UDP 失败时 **添加节点** 填 B `IP:43124` | 连接发起成功 |
| 7 | B 打开顶栏 **发现 → 群组** | 见 A 的 `autoDiscover` 群；加入后切群聊天 |
| 8 | B **发现 → 成员** 点 A | 进入私聊会话 |

UDP 发现失败时走步骤 6（发现面板「无法发现？连接对端」· `host:port`）。步骤 6 的「添加节点」与顶栏网络菜单已拆开，见 [02](./02_技术实现建议.md) §13.6。

### 6.3 通过标准

手验全部步骤无报错、文件 SHA256 一致。本仓库 **不保存** 双机勾选表；有结果可记团队笔记，勿把 loopback 绿当成 §6.2 已测。
