# 05_测试与联调发布

> **测试分层**、联调手验、视觉抽检与发布前命令。验收条文见 [06_验收与里程碑计划.md](./06_验收与里程碑计划.md)。索引 [00_文档导航.md](./00_文档导航.md)。

### 磁盘路径约定（防撑爆）

| 用途 | 路径 | 可否清 |
|------|------|--------|
| 构建输出 | 仓库 `out/` · `dist/` | 可删，下次 `build` 再生 |
| 测试临时库/截图 userData | 仓库 **`.lanpm/tmp/`**（`tests/lanpmTemp.ts`） | 测完应自动删；残留可 `rm -rf .lanpm/tmp` |
| Stub 文件总线 | 仓库 **`.lanpm/stub-bus/`**（可用 `LANPM_STUB_BUS_DIR` 覆盖） | 可清；联调前可空目录 |
| 视觉截图产物 | 仓库 `.lanpm/visual-screenshots/` | 可清 |
| 应用持久数据 | `app.getPath('userData')`（Linux 常为 `~/.config/lanpm`） | **勿当缓存清** |
| Electron 二进制缓存 | `~/.cache/electron` · `~/.cache/electron-builder` | 可清（可重建，下次会再下载） |

**原则**：持久数据 → 稳定目录（userData）；可重建工具链 → `~/.cache`；连续自动化测试 → **仓库内 `.lanpm/`**，禁止默认堆 `/tmp/lanpm-*`。


### 1.3 CI / 本地发布前

```bash
npm run verify:release-gate   # 推荐：含 docs-code、visual、project、m7、截图（Linux 自动 xvfb）
# 或分步：
npm run verify:project && npm run verify:m7
npm run build && xvfb-run -a npm run verify:visual-screenshots
```

CI：

| Workflow | 触发 | 用途 |
|----------|------|------|
| `verify.yml` | push/PR `master`·`main`·`develop` · **Run workflow** | 三平台 `verify:m7`（日常打版门禁） |
| `release.yml` | **Run workflow**（tag + ref=master）· push `v*` | 三平台包 → **CI 自动 Publish**（含 deb） |
| `sync-r2.yml` | `Release` 成功 · **Run workflow** | **可选** R2 独立下载页；未配置 `R2_*`/`BASE_URL` Variables 时跳过 |

**重跑 CI（勿点 Re-run failed jobs — 会沿用旧 workflow YAML）：**

1. **verify**：Actions → `verify` → Run workflow（分支 `master`）
2. **release 全量重建**：Actions → `Release` → tag=`v1.0.0-rc.N` · `publish_only`=false
3. **仅发布已有 draft**（资产已上传）：`publish_only`=true
4. **R2**：Release 成功后自动跑；或 `Sync Release to R2` 手动填 tag

**Immutable Releases 注意：** 已发布的 Release 不可再追加资产；全量重跑需新 tag 或先在 GitHub 删除旧 Release。

无头 PNG 截图 `verify:visual-screenshots` 仅本地/发版手跑，见 §2。

手验项见 [06](./06_验收与里程碑计划.md) **§2.6**（三平台真机、性能、双机、I18N 折行等）。

### 2.3 截图与 RC

```bash
npm run build && xvfb-run -a npm run verify:visual-screenshots   # Linux 无头；输出 .lanpm/visual-screenshots/
```

无头流程会在 `demo-project` 写入 2 条带排期的种子任务（标题含 `截图·设计评审`），等待甘特 `.bar` 任务条（宽≥24px）≥2 条后截图，并写入 `capture-meta.json`；校验亮暗 MD5 不同（**不以 PNG 体积判断甘特是否为空**，CI 无头压缩差异大）。

**注意**：Linux + `xvfb` 下 `capturePage` 对甘特 **SVG 网格** 的还原可能不如 `npm run dev` 真窗口（常见现象：亮色图区偏黑，但交互界面正常）。**V-14b 甘特以本机 `dev` 肉眼为准**；PNG 用于回归「有无崩溃/主题切换」，不作甘特像素级 SSOT。

截图存本地（**勿提交仓库**），命名 `{theme}_{page}.png`（`setup` · `chat` · `board` · `tree` · `gantt` · `files` · `cockpit`）。**自动化**仅覆盖生成与主题区分；**SEM / HOV / 有任务时的甘特时间轴**仍须对照本表 §2.2 人工勾选。完成后在 [06](./06_验收与里程碑计划.md) §2.5 勾选「亮/暗主题视觉抽检（人工）」。

## 6. 局域网真网联调（M6）

### 6.1 环境

- ≥2 台同网段或 VPN 互通；防火墙放行 UDP `43123`、TCP `43124`（[02](./02_技术实现建议.md) §13.5）。

### 6.2 步骤

| # | 操作 | 预期 |
|---|------|------|
| 1 | 启动等待 3–15s | UDP 发现对端 |
| 2 | A 发消息 | B 加密收到 |
| 3 | A 上传 10MB | B 下载 SHA256 一致 |
| 4 | 同用户双设备 | 在线态合并 |
| 5 | A 断网 20s 恢复 | 自动重连、离线补同步 |
| 6 | UDP 失败时 **添加节点** 填 B `IP:43124` | 连接发起成功 |
| 7 | B 打开顶栏 **发现 → 群组** | 见 A 的 `autoDiscover` 群；加入后切群聊天 |
| 8 | B **发现 → 成员** 点 A | 进入私聊会话 |
