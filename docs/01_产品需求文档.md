## 1. 产品概述

### 1.1 产品定位

一款**分布式局域网协作客户端**：**本体是项目管理（看板/任务树/甘特图）与企业级能力（驾驶舱/AI 评估）**；聊天与文件为项目协作服务（借鉴飞秋/飞鸽的局域网通讯体验，但不以 IM/传文件对标为产品目标）。**无中心服务器**，所有数据在群组内点对点同步。**天生跨平台**（Windows / macOS / Linux，x86_64 与 ARM 同步规划），客户群体含通用办公网与**信创环境**（统信/麒麟等国产 OS 及飞腾/鲲鹏等 CPU）。

### 1.2 核心理念

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│   LAN（无中心 · 数据不出域） + PM（看板 / 树 / 甘特 / 驾驶舱）   │
│                          +                                  │
│     聊天 · 文件（为项目服务） + AI 辅助（可选脱敏外呼）          │
│                                                             │
│   天生跨平台（Win/macOS/Linux · x64/ARM 同步）· 含信创客户     │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 1.3 技术栈（目标选型）

| 层级   | 技术选型                            | 理由            |
| ---- | ------------------------------- | ------------- |
| 桌面框架 | Electron                        | **天生跨平台**（Win/macOS/Linux · x64/ARM 同步规划）；含信创 OS 部署面   |
| 前端框架 | React 18 + TypeScript           | 生态成熟、工程化完善、便于后续多端迁移与后端对接 |
| UI 组件库 | Ant Design 5.x + CSS Modules   | 企业协作密集型界面；见 `docs/05` §8 |
| 客户端状态 | Zustand                        | 跨视图/群组状态管理 |
| 甘特图组件 | `gantt-task-react`             | M4 集成；与任务数据同源 |
| 本地存储 | IndexedDB + SQLite              | 支持大量离线数据      |
| 网络通信 | WebRTC (P2P) + UDP 广播           | 局域网发现 + 点对点传输 |
| 数据同步 | CRDT (Yjs)                      | 分布式最终一致性      |
| 加密   | Node.js Crypto (AES-256-GCM)    | 局域网传输加密       |
| 文件预览 | LibreOffice 本地转换 | Office 文件本地预览，数据不出域 |

## 3. 用户标识与身份

### 3.1 唯一标识规则

> **核心原则**：同一用户可在多台电脑登录，视为同一人


| 字段    | 说明           | 示例                  |
| ----- | ------------ | ------------------- |
| 用户名   | 显示名称         | 张三                  |
| 后缀    | 可选，用于区分同名用户  | `-87`、`-93`、`-2401` |
| 完整显示名 | 用户名 + 后缀（如有） | 张三 / 张三-87          |
| 设备列表  | 该用户的所有登录设备   | 办公本、笔记本             |
| 在线状态  | 任一设备在线即为在线   | ✅ / ❌               |


### 3.2 后缀生成规则


| 场景           | 处理方式                               |
| ------------ | ---------------------------------- |
| 首次注册时用户名未被占用 | 不加后缀                               |
| 首次注册时用户名已存在  | 自动添加 `-yymm`（如 `-2401` 表示 2024年1月） |
| 用户手动修改       | 允许，但需保证群组内唯一                       |


### 3.3 ID 结构示例

```javascript
{
  "userId": "zhangsan",                    // 唯一标识（含后缀）
  "displayName": "张三-87",                 // 显示名称
  "suffix": "-87",                         // 后缀（可选）
  "devices": [
    { "deviceId": "office-pc", "name": "办公本", "lastSeen": "2026-01-10" },
    { "deviceId": "laptop", "name": "笔记本", "lastSeen": "2026-01-09" }
  ],
  "online": true                           // 任一设备在线
}
```

```javascript

  language: 'javascript',  // 自动检测或手动选择

  console.log("Hello LanPM");
```

**支持的语言**：JavaScript/TypeScript/Python/Java/Go/Rust/HTML/CSS/JSON/Shell 等主流语言

### 6.5 消息已读回执


| 状态  | 图标  | 说明       |
| --- | --- | -------- |
| 发送中 | ⏳   | 正在传输     |
| 已发送 | ✅   | 已送达对方客户端 |
| 已读  | ✅✅  | 对方已阅读消息  |

#### 已读判定与冲突规则（补充）

- 同一 `userId` 下任意一台设备读到消息，即判定该用户“已读”。
- 客户端只对“本人已读状态”做回滚兜底，不影响其他用户消息状态。
- 冲突处理遵循“最新事件优先”（按 Lamport 时间戳或本地逻辑时钟，取更晚事件；无中心服务器）。
- 已读状态跨设备同步，允许最终一致性短暂延迟。

## 12. 领导驾驶舱

### 12.1 界面布局

领导跨群一眼视图（实现：`CockpitView` · 路由 `/cockpit`）。**操作层级**：周报为主 CTA（`type="primary"`）；月报默认按钮；AI 评估为 `type="text"` 次要；API Key 文字按钮；返回当前项目为幽灵按钮（不抢戏）。

**滚动契约**：`MainLayout.mainCockpit` 禁止主区滚动；`ViewHeader` 固定；内容区 `.scrollBody` 单容器纵向滚动（`flex:1 1 0` · `overflow-y:auto` · `scrollbar-gutter:stable`），月报展开后仍可滚至「部门完成率」底部。

**首屏信息架构**（自上而下，均在 `scrollBody` 内）：

```
┌─────────────────────────────────────────────────────────────────┐
│  驾驶舱     [返回…]  [周报★] [月报] [AI评估] [API Key]  ← 固定   │
├─────────────────────────────────────────────────────────────────┤
│  ▼ scrollBody（单滚动容器）                                      │
│  需关注 │ 延期 N · 风险 M：项目名…  [看看板]                     │
│  领导摘要（单一岛）│ 本周完成·环比·下周到期·需关注数            │
│                   │ 项目数·进行中·风险·延期（两排紧凑，禁双岛） │
│  需关注任务 Top N（延期/落后 · 项目·负责人·截止 · 进看板）       │
│  项目进度（排序：延期 → 风险 → 正常）                            │
│  部门完成率（`user.department` 聚合；未分配单独桶）              │
│  报表输出（生成后置底 · 默认折叠 teaser · 展开限高）             │
└─────────────────────────────────────────────────────────────────┘
```

- **需关注（项目级）**：`delayed` / `risk` 项目条；全正常时健康文案。
- **领导摘要（单一岛）**：周执行（本周完成 / 周环比 / 下周到期 / 需关注任务数）与项目健康（`totalProjects` / `inProgressCount` / `riskProjectCount` / `delayedCount`）同岛两排紧凑展示；**禁止**再出现独立 KPI 四卡岛。
- **需关注任务（任务级）**：延期 + `behind` 任务 Top 8；可点进对应项目看板。
- **项目健康**：`delayed` / `risk` / `normal`（与看板 `scheduleHealth` 规则同源）；`sortCockpitProjects` 排序。
- **部门**：`doneCount` / `taskCount` / `completionPercent`；随 `scrollBody` 滚（不嵌套常驻竖滚）。
- **报表**：周报/月报/评估生成后出现在页底；复制与来源 meta 保留。
- **视觉**：岛感卡片（`--lanpm-shadow-island` · `--lanpm-surface-elevated`）；亮暗成对。自动化守卫见 `tests/static/verify-visual.ts`（CK-401～411）。

### 12.3 API-Key 配置

```javascript
// 支持的 AI 服务
{
  "provider": "openai" | "anthropic" | "custom",
  "apiKey": "sk-xxx",
  "baseUrl": "https://api.openai.com/v1",  // 可配置代理
  "model": "gpt-4",
  "enabled": true,                          // 是否启用外部 AI 功能
  "dataPolicy": "desensitized-only"         // 仅允许脱敏字段外发
}
```

#### AI 能力


| 功能   | 输入        | 输出          |
| ---- | --------- | ----------- |
| 任务审核 | 任务标题+描述   | 评分 + 改进建议   |
| 进度评估 | 项目任务列表+进度 | 风险识别 + 建议   |
| 周报生成 | 一周任务变更    | 结构化的周报文本    |
| 阻塞预警 | 延期任务      | 高亮提醒 + 建议方案 |


> **隐私保护**：API 调用仅发送脱敏数据（任务标题、状态、进度），不发送完整聊天记录或文件内容

#### AI 分阶段策略（补充）

- P0：提供 API-Key 配置、手动触发 AI 审核/评估能力。
- P1：增加自动化评估（定时巡检、阻塞预警推送）。
- 即使设备可联网，默认仍遵循“最小外发”原则，只传审核所需脱敏数据。
