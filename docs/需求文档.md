# LanPM 需求文档（基于现有原型）

## 1. 文档目的
基于当前 `index.html` 单文件原型与 `plan.md` 重构计划，明确下一阶段产品需求边界、功能优先级与验收标准，作为后续迭代实现依据。

## 2. 项目背景与目标
- 当前已有可运行的苹果风格原型，包含聊天区、任务看板、任务树、甘特图等主要界面能力。
- 下一阶段目标：在保留现有交互基础上，进一步做结构收敛与体验升级，形成更聚焦、更紧凑、可扩展的局域网项目管理界面。
- 核心方向：
  - 顶部栏增强：项目切换 + 模糊搜索；
  - 主布局收敛：移除右侧面板与成员侧栏；
  - 底部全屏视角统一为 4 类：聊天 / 看板 / 任务树 / 甘特图；
  - 看板支持原生拖拽改状态；
  - 视觉细节与动效进一步苹果化。

## 3. 从现有原型推断的已具备能力
### 3.1 已有模块（来自 `index.html`）
- 顶部栏（毛玻璃风格）与主导航（项目 / 领导驾驶舱）。
- 项目视图下的聊天主区（消息列表、输入框、任务快捷创建提示）。
- 右侧任务看板小面板（mini kanban）。
- 底部视图标签与详情区域，已存在看板、待办、任务树、甘特图等视图容器。
- 领导驾驶舱相关区域（作为扩展管理视角）。

### 3.2 当前痛点（来自 `plan.md`）
- 项目切换能力不足，无法方便切项目上下文。
- 左右栏信息过多，主聊天工作流不够聚焦。
- 视图定义仍有“独立待办”入口，与“看板状态化管理”目标重复。
- 交互上仍需强化拖拽流转与过渡体验。

## 4. 需求范围（本轮）
### 4.1 信息架构与导航
- 顶部栏新增“项目切换下拉”。
- 顶部栏新增“模糊搜索”入口，可搜索任务、消息、成员（至少支持任务标题关键字）。
- 保持毛玻璃视觉基调，避免破坏已有苹果风格。

### 4.2 布局重构
- 移除右侧面板（mini kanban 区域）。
- 移除成员侧栏，成员信息由项目上下文或弹层承载。
- 聊天区域作为默认主工作区，确保输入、消息、任务联动路径简洁。

### 4.3 底部视角统一（4 视角）
- 聊天：即时消息与任务协同入口。
- 看板：任务状态流转主界面（待办/进行中/已完成）。
- 任务树：层级任务结构展示与展开折叠。
- 甘特图：任务时间轴与状态条展示。

说明：原“独立待办”视角并入看板，不再单独作为一级视角。

### 4.4 看板拖拽能力
- 使用 HTML5 Drag & Drop API 实现卡片跨列拖拽。
- 状态列至少包含：待办、进行中、已完成。
- 拖拽后需立即更新 UI 状态（后续可扩展持久化）。

### 4.5 视觉与交互体验
- 缩小冗余间距，提升信息密度。
- 卡片、面板、按钮层次与阴影统一。
- 关键操作提供过渡动画，避免突兀切换。

## 5. 非功能需求
- 兼容现代 Chromium 内核浏览器（桌面端优先）。
- 保持单文件原型可运行性（短期），后续可按模块拆分。
- 无后端依赖时也可本地演示主要流程（静态数据驱动）。

## 6. 验收标准（MVP）
- 可以在顶部栏切换项目，并同步更新主区项目上下文展示。
- 可以通过搜索框按关键字过滤至少一类实体（任务）。
- 页面不再出现右侧面板与成员侧栏。
- 底部仅保留 4 个视角入口：聊天、看板、任务树、甘特图。
- 看板支持跨列拖拽，拖拽后状态即时变化且可见。
- 视觉保持统一苹果风格，交互无明显卡顿或闪烁。

## 7. 里程碑建议
- M1（结构改造）：顶部栏增强 + 布局收敛 + 视角整合；
- M2（核心交互）：看板拖拽 + 状态流转逻辑；
- M3（体验打磨）：样式统一、动效优化、验收回归。

## 8. 暂不纳入本轮
- 多用户实时同步与冲突处理；
- 后端持久化、权限体系、审计日志；
- 复杂报表与企业级驾驶舱扩展。

## 9. 后续落地建议
- 先按 `plan.md` 执行结构、样式、逻辑三步重构；
- 每完成一个里程碑更新 `plan.md` 与 `CHANGELOG.md`；
- 若后续拆分代码结构，建议新增 `docs/技术设计.md` 与 `docs/交互说明.md`。
