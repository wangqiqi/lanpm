# 聊天页 CPU / 内存优化备忘

> **来源**：2026-07-31 代码评审（只读，未改实现）  
> **现象**：进入聊天相关能力后 CPU / 内存占用偏高（消息较多时更明显）  
> **范围**：`ChatView` · `MessageBubble` · 插件菜单/Slot · 成员侧栏 · 已读标记 · 代码高亮 · 消息缓存  
> **关联版本**：消息右键菜单 v1.78.8+ · 消息上下文 v2 v1.79.0+  
> **文档性质**：性能债 backlog + 评审记录（**非** `01`/`04`/`06` 规范 SSOT；立项后见 `06_ROADMAP` · `plan.md`）

---

## 1. 问题摘要

### 1.1 CPU

| 严重度 | 问题 | 根因概要 | 主要位置 |
|--------|------|----------|----------|
| **High** | 每条消息独立拉插件右键菜单 | `usePluginMenus` 在气泡内挂载 → N 次 `plugin.listMenus()` + N 个事件监听 | `MessageBubble.tsx` · `usePluginMenus.ts` |
| **High** | 每条消息挂插件 context 槽 | `PluginZoneHost` → `useSlotPlugins` → N 次 `listSlotPlugins` | `MessageBubble.tsx` · `PluginSlot.tsx` |
| **High** | 列表全量重渲染 | `ChatView` 内联回调 + `MessageBubble` 无 `memo`，任意 state 变更重绘全部气泡 | `ChatView.tsx` · `MessageBubble.tsx` |
| **Medium** | 成员侧栏定时刷新 | 侧栏打开时每 3s `loadMembers` | `MemberList.tsx` |
| **Medium** | 已读标记扫全表 | `useMarkRead` 依赖整份 `messages`，新消息频繁触发 effect | `useMarkRead.ts` |
| **Medium** | 代码块高亮成本 | `highlight.js`；无语言时 `highlightAuto` 更贵；**折叠前已全量高亮**；父组件重渲染时重复计算 | `CodeBlock.tsx` · `highlightSetup.ts` |
| **Medium** | DM 侧栏连带重绘 | `DmSessionBar` 订阅 **整表** `messagesByGroup`，任意群新消息都触发 DM 条重算 | `DmSessionBar.tsx` |
| **Medium** | 消息入库全量排序 | `mergeMessage` / `upsertMessage` 每次 `sortMessages` O(n log n) | `chatStore.ts` |
| **Medium** | 插件菜单 IPC 冗余 | `listMenus()` 返回 **全部** location，客户端再 filter；N 气泡 = N 次全量拉取 | `usePluginMenus.ts` |
| **Medium** | 插件启用惊群 | `PLUGIN_ENABLED_CHANGED_EVENT` 触发时，N 个 `usePluginMenus` / `useSlotPlugins` **同时** reload | `usePluginMenus.ts` · `PluginSlot.tsx` |
| **Low** | 置顶条扫全量消息 | `PinnedMessagesBar` 每次 render `new Map(messages)` | `PinnedMessagesBar.tsx` |
| **Low** | 气泡内 Router 钩子 | 每条 `MessageBubble`：`useNavigate` + `useParams` + `useLocateTask` | `MessageBubble.tsx` |
| **Low** | 顶栏网络轮询 | 每 8s 静默刷新网络状态 | `TopBar.tsx` |
| **场景** | 语音 / 会议 / 发现配对 | 各自 `setInterval` 或媒体采集，仅对应功能开启时 | 见 §4 |

### 1.2 内存

| 严重度 | 问题 | 根因概要 | 主要位置 |
|--------|------|----------|----------|
| **High** | 消息列表全量挂载 DOM | 无虚拟列表；N 条消息 = N 棵 React 子树 + Ant Design Dropdown 等 | `ChatView.tsx` |
| **High** | 插件钩子 per-bubble | 除 CPU 外，每条气泡独立 state / listener / 闭包，随 N 线性增长 | `MessageBubble.tsx` |
| **Medium** | 群消息常驻内存 | `messagesByGroup` 随 `loadOlder` 累积，切群不自动裁剪（仅有 `evictGroup`） | `chatStore.ts` |
| **Medium** | 大数组向下传递 | 每条 `MessageBubble` 接收完整 `members` + `tasks` 引用，阻碍 memo | `ChatView.tsx` · `MessageBubble.tsx` |
| **Medium** | Markdown / 高亮结果常驻 | `MarkdownView`、高亮 HTML 挂在可见区外气泡上仍占内存 | `ChatMessageText.tsx` · `CodeBlock.tsx` |
| **Low** | 通知去重 Set 无界 | `notifiedIds` 模块级 `Set`，长跑可能持续增长 | `useChatNotifications.ts` |
| **Medium** | Markdown 解析常驻 | `ReactMarkdown` + `remark-gfm` 每条文本段实例化；无 `memo` | `ChatMessageText.tsx` · `MarkdownView.tsx` |
| **Medium** | 折叠代码仍全量高亮 | `CodeBlock` 先 `highlightCode` 再 CSS 折叠，长代码 **HTML 字符串**已生成 | `CodeBlock.tsx` |
| **Medium** | DM 预加载占内存 | `DmSessionBar` 对全部 DM `loadMessages`，消息进 `messagesByGroup` 常驻 | `DmSessionBar.tsx` · `chatStore.ts` |
| **Low** | 图片/文件预览 | 消息内图片无 `loading="lazy"` / 视口外卸载 | `MessageBubble.tsx` |

**与消息上下文 v2**：`resolveReplyQuote` 在 `map` 内逐条计算，CPU 有成本但**低于** N×插件 IPC；i18n 修复**不是**性能主因。

## 2. 问题详述

### 2.1 每条气泡调用 `usePluginMenus`（High）

`MessageBubble` 内：

```ts
const pluginContextMenuItems = usePluginMenus('chat.message.context')
```

`usePluginMenus` 在 **每个气泡实例** mount 时：

1. 调用 `getLanpmApi().plugin.listMenus()`
2. 注册 `PLUGIN_ENABLED_CHANGED_EVENT` 监听

**影响**：消息条数为 N 时，约 **N 次 IPC + N 个 listener**。历史消息多的群进入聊天页即尖峰。

**引入时间线**：v1.78.8 `menus[]` POC（`chat.message.context`）。

---

### 2.2 每条气泡挂载 `PluginZoneHost`（High）

己方 / 对方气泡各有一处：

```tsx
<PluginZoneHost zone="context" context={messageContext} />
```

链路：`PluginZoneHost` → `PluginSlotHost` → `useSlotPlugins('chat.message.action')` → `listSlotPlugins`。

**影响**：N 条消息 ≈ **N 次** slot 查询（与 §2.1 叠加）。插件槽位应在 **会话级** 拉一次并下发，不应按消息实例化。

---

### 2.3 `ChatView` 全量重渲染（High）

- 消息 `map` 内大量 **inline 回调**（`onLinkFileToTask` 等），每次父组件 render 引用都变。
- `MessageBubble` **未** `React.memo`。
- 列表内还有 `pinnedIds.includes` / `selectedMsgIds.includes`（O(消息数×选中/置顶数)）。
- `resolveReplyQuote` 在 `map` 内对每条带 `replyToMsgId` 的消息执行（父组件任一 state 变即重算）。

**影响**：打字、多选、引用回复、置顶条交互时 CPU 持续偏高，消息越多越明显。

---

### 2.4 成员侧栏 3 秒轮询（Medium）

`MemberList`：`PRESENCE_POLL_MS = 3_000`，侧栏打开时 `setInterval(onRefresh)` → `loadMembers`。

单独看不致命，与 §2.1–2.3 叠加会放大体感。

---

### 2.5 `useMarkRead` 依赖整份 messages（Medium）

`useMarkRead(groupId, visibleMessages, …)` 在 `messages` 引用/内容变化时重新 filter 全量并 `markRead`。

实时收消息场景下 effect 触发频繁。

---

### 2.6 代码块 `highlight.js`（Medium）

`CodeBlock` 用 `useMemo(() => highlightCode(...))`；父组件频繁重渲染或 `highlightAuto` 路径时，长代码块成本高。

**补充**：折叠 UI（>12 行）仅隐藏溢出，**高亮在 mount 时已完成**；折叠态仍保留完整 `dangerouslySetInnerHTML` 字符串，占内存。

---

### 2.7 `DmSessionBar` 订阅全量 `messagesByGroup`（Medium）

```ts
const messagesByGroup = useChatStore((s) => s.messagesByGroup)
```

任意群 `upsertMessage` 都会换新 `messagesByGroup` 引用 → **DM 会话条整组件重渲染**，即使当前在看别的群。

同时 `useEffect` 对 `sessionGroupIds` 内每个 DM 调用 `loadMessages(id)`，会把多路会话消息 **预载入内存**（见 §2.8）。

---

### 2.8 `chatStore` 每次 upsert 全量排序（Medium）

```ts
function mergeMessage(...) {
  ...
  return sortMessages([...list, message])  // 或 patch 后仍 sortMessages
}
```

实时收消息、delivery 状态更新、撤回 patch 都会触发 **O(n log n)** 排序 + 新数组分配。大群高频更新时主线程与 GC 压力明显。

**目标态**：lamport 单调追加走尾部 insert；仅乱序/编辑走局部修正。

---

### 2.9 `usePluginMenus` 拉全量 + 惊群（Medium）

单次 `listMenus()` 返回所有 `location` 的菜单项，再在客户端 `filter(location)`。N 条气泡 = **N 次相同 IPC  payload**。

`PLUGIN_ENABLED_CHANGED_EVENT` 时，每个 hook 实例各自 `loadMenus()` → **惊群**（IPC + setState × N）。

**目标态**：主进程按 `location` 查询或 Renderer 单例缓存 + 单次 reload 广播给订阅者。

---

### 2.10 置顶条与文本解析（Low–Medium）

`PinnedMessagesBar`：有置顶时每次父组件 render 执行 `new Map(messages.map(...))`，复杂度 O(消息总数)，应复用 `ChatView` 已有 `messageById`。

`ChatMessageText`：`splitMentionSegments` / `splitTaskRefSegments` / `shouldRenderChatMarkdown` **无 memo**，父级全量 reconcile 时重复切分；含 Markdown 段则 mount `ReactMarkdown`。

---

### 2.11 气泡内 Router / 定位钩子（Low）

每条 `MessageBubble` 独立：

- `useNavigate()` · `useParams()` · `useLocateTask(gid)`

Router 订阅与 `useCallback` 闭包随 N 增长。应提升到 `ChatView` 或 context，气泡只收稳定函数引用。

---

### 2.12 媒体与附件（Low）

文件/截图消息若内联 `<img>`，默认 eager 解码；长列表滚动时 **解码与 GPU 纹理** 随历史条数累积。视口外应占位或 `loading="lazy"` + 卸载 `src`。

---

## 3. 验证方法（不改代码可自测）

| 步骤 | 操作 | 若成立则说明 |
|------|------|----------------|
| 1 | DevTools → Performance，进大群录 10s | Scripting 尖峰在 `listMenus` / `listSlotPlugins` / React reconcile → §2.1–2.3 |
| 2 | 关闭成员侧栏再对比 | CPU 明显下降 → §2.4 有贡献 |
| 3 | 小群 vs 大群 | 仅大群热 → N×气泡钩子为主因 |
| 4 | 只打字、不收消息 | 仍热 → §2.3；仅收消息时热 → §2.5 |
| 5 | 开 DM 面板、切大群对比 | DM 条随他群消息闪烁/CPU → §2.7 |
| 6 | Performance：收 100 条连续消息 | `sortMessages` / `mergeMessage` 栈帧突出 → §2.8 |
| 7 | Memory：含长代码折叠消息 | 折叠后 Heap 仍含大段 HTML 字符串 → §2.6 / §2.10 |

## 5. 优化建议（按优先级）

### P0 — 结构性（预期收益最大）

1. **插件菜单单例化**  
   - 在 `ChatView`（或聊天 Provider）调用 **一次** `usePluginMenus('chat.message.context')`。  
   - 通过 props / context 传给 `MessageBubble`，禁止每条气泡独立 hook。

2. **消息 context 插件槽会话级加载**  
   - `chat.message.action` 的 `listSlotPlugins` 提升到 `ChatView` 一层。  
   - 评估是否仍需 **每条消息** 一个 `PluginZoneHost`；若插件不需 per-message 实例，改为群级锚点或按需挂载（例如仅 hover/选中时）。

3. **列表渲染减负**  
   - `MessageBubble` 包 `React.memo` + 稳定回调（`useCallback` / 抽子组件）。  
   - `replyQuote` 用 `useMemo` 按 `msgId` 缓存，或预计算 `Map<msgId, ResolvedReplyQuote>`。  
   - `pinnedIds` / `selectedMsgIds` 改为 `Set` 做 O(1) 查找。

### P1 — 中等收益

4. **成员在线**  
   - 轮询间隔从 3s 提到 10–15s，或改为推送/事件驱动；侧栏折叠时 **停止** interval。

5. **已读标记**  
   - 仅对新到达消息 id 增量 `markRead`，避免每次扫全量 `messages`。  
   - 对 `messages` 依赖改为「最后一条他人消息 id」或 debounce。

6. **代码高亮**  
   - 语言未知时避免 `highlightAuto` 扫全库；限制单次高亮长度。  
   - 虚拟列表（长会话）减少同时挂载的 `CodeBlock` 数。

### P2 — 体验与观测

7. **性能预算**（✅ **v1.87.0** — 见 `docs/specs/009-chat-perf-observe/spec.md` §Budget）  
   - **CPU**：首屏 3s Scripting < 800ms；10s 滚动 Scripting < 500ms（packaged build）。  
   - **内存**：DOM 亚线性于历史条数；Heap 滚动/切群无阶梯暴涨。  
   - **静态守卫**：`verify:chat-perf-observe` + `verify:chat-perf*` 禁止 `MessageBubble` 内 `usePluginMenus` / `useSlotPlugins`。

8. **文档**  
   - `插件开发.md` 注明：`chat.message.context` 菜单项由 Host 聚合加载，插件作者不应假设 per-bubble 生命周期。

### P0′ — 内存专项（与 CPU 并列）

9. **虚拟列表（虚拟滚动）**  
   - 采用 `@tanstack/react-virtual` 或等价方案，只 mount 视口 ± 缓冲区行。  
   - 长会话 **DOM 节点数** 与 **React Fiber** 与视口高度相关，而非与历史总条数线性相关。  
   - 与「上拉加载更早消息」兼容：prepend 时保持 scroll anchor（已有 `useNewMessageScroll` / `scrollMemory` 可复用思路）。

10. **消息内存窗口（Renderer 侧）**  
    - `messagesByGroup` 可设软上限（如每群保留最近 2000 条在内存，更早仅 SQLite 可查）。  
    - 切离聊天 Tab / 切群时：非当前群可 **降级** 为「仅保留 lastMessage + 未读计数」，需要时再 `loadMessages`。  
    - 已有 `evictGroup`（`chatStore.ts`）可在「清理本机缓存」路径主动调用。

11. **缩小子组件 props 面**  
    - `MessageBubble` 不要传完整 `tasks` / `members`：文本消息只传 `mentionDisplayNames` 或 `memberById` 的 **只读快照**；含 `#任务` 的消息再传相关 task 子集。  
    - 减少 props 引用变化 → `React.memo` 才有效。

12. **富文本 / 代码懒处理**  
    - 视口外气泡：纯文本占位，不进 `MarkdownView` / `highlightCode`。  
    - 高亮结果按 `(language, codeHash)` 缓存到 `Map`（LRU，上限如 200 条）。  
    - 禁止 `highlightAuto` 扫全语言库；未知语言用 `plaintext`。

13. **右键菜单按需挂载**  
    - 对齐微信/QQ：**一个** 全局 `Dropdown` / ContextMenu，右键时设置 `activeMsgId`，而非每条气泡包一层 `Dropdown`（减少 Ant Design 内部监听与 DOM）。

14. **模块级缓存去界**  
    - `useChatNotifications` 的 `notifiedIds`：按会话 LRU 或仅保留最近 10k msgId，避免长跑无限增长。  
    - `scrollMemoryByGroup`：仅保留最近访问的 K 个群（如 20）。

15. **Store 写入减负**  
    - `upsertMessage`：追加路径避免全表 `sort`；`deliveryStatus` patch 原位更新。  
    - `DmSessionBar` 改为 `useChatStore(s => s.messagesByGroup[sessionId])` 或 `lastMessage` 派生字段，**禁止**订阅整表。  
    - DM 列表仅加载可见会话最后一页，或主进程提供 `listDmPreviews` 轻量接口。

16. **插件 IPC 去重**  
    - `listMenus({ location })` / `listSlotPlugins` 会话级缓存 + `PLUGIN_ENABLED_CHANGED` **一次** invalidate。  
    - 文档约定插件作者：菜单命令幂等，不依赖 per-bubble mount。

17. **文本/Markdown 缓存**  
    - `ChatMessageText` / `MarkdownView` 包 `memo`；按 `msgId + textHash` 缓存解析结果。  
    - `CodeBlock`：**展开后再高亮**，或折叠态只显示行数占位 + 纯文本；高亮放 `requestIdleCallback` / Worker（远期）。

18. **媒体懒加载**  
    - 图片 `loading="lazy"` + 视口外 `src` 置空；大图缩略图策略对齐微信「点击再看原图」。

19. **Zustand 选型**  
    - `ChatView` 动作类 selector（`sendText` 等）用 `useChatStore.getState()` 在 handler 内调用，减少 15+ hook 订阅开销（次要，优先 §2.1–2.3）。

### P3 — 快速收益（改动小，可穿插）

| 项 | 做法 | 预期 |
|----|------|------|
| 置顶条 | 传入 `messageById: Map` 或仅 `pinnedMessages: ChatMessage[]` | 去掉 O(N) Map |
| `selectedMsgIds` | `useState<Set<string>>` | 查找 O(1) |
| `formatTime` | 模块级纯函数已 OK；配合 memo 减少子树刷新 | 微优化 |
| `PinnedMessagesBar` | `memo` + 稳定 `onJump`/`onUnpin` | 减少置顶区重绘 |
| 开发态 | 生产包对比 `npm run dev` | 排除 HMR 误判 |

## 6. 建议实施顺序（Sprint 候选）

| 序 | 任务 | 预估 | 验收（CPU / 内存） |
|----|------|------|-------------------|
| 1 | 抽出 `ChatPluginMenusProvider`，移除气泡内 `usePluginMenus` | 小 | ✅ **v1.83.0** — IPC `listMenus` 仅 1 次；气泡 mount 无插件 hook |
| 2 | 会话级 slot 缓存 + 移除/按需 `PluginZoneHost` | 中 | ✅ **v1.83.0** — `listSlotPlugins` 与 N 解耦 |
| 3 | `MessageBubble` memo + 稳定 props + 单例 ContextMenu | 中 | ✅ **v1.83.0** — 打字时无全列表 reconcile；DOM 中 Dropdown 数量不随 N |
| 4 | **虚拟列表** | 中 | ✅ **v1.83.0** — `@tanstack/react-virtual`；与按日分组兼容 |
| 5 | 成员轮询 / 已读增量 | 小 | ✅ **v1.84.0** — 侧栏关无 interval；收消息 CPU 平滑 |
| 6 | 高亮/Markdown 懒加载 + LRU 缓存 | 小 | ✅ **v1.84.0** — 折叠长代码延后高亮；`ChatMessageText` memo |
| 7 | `messagesByGroup` 窗口 + 切群降级 | 中 | ✅ **v1.84.0** — 2000 条/群 + `downgradeInactiveGroups` |
| 8 | `verify:chat-perf` 防回归 | 小 | ✅ **v1.83.0** — `npm run verify:chat-perf` |
| 9 | `upsertMessage` 增量排序 + DM 轻量订阅 | 小 | ✅ **v1.84.0** — 追加 O(1)；DM 行级 selector |
| 10 | 插件 IPC `location` 过滤 + 单点 invalidate | 小 | ✅ **v1.85.0** — `listMenus(location?)` payload 与 N 解耦 |
| 11 | 代码折叠延后高亮 + Markdown memo | 小 | ✅ **v1.84.0** — 长代码折叠 Heap 下降 |

## 9. 行业对照：QQ / 微信 / 同类 IM 怎么做

> 以下为公开架构模式与客户端常见实践归纳，**非**腾讯/微信官方实现细节。

| 维度 | QQ / 微信 / Telegram 等常见做法 | LanPM 现状 | 目标态 |
|------|--------------------------------|------------|--------|
| **消息列表** | 虚拟列表 / Cell 复用；上万条可滑 | 全量 `map` 渲染 | §5 P0′ 虚拟列表 |
| **长按/右键菜单** | 菜单定义注册 **一次**；交互时带 `messageId` 弹出 | 每条气泡 `usePluginMenus` + `Dropdown` | §5 P0 单例菜单 |
| **扩展能力** | 工具栏、「+」、独立页；**不**每条消息挂插件容器 | 每条 `PluginZoneHost` | §5 P0 会话级/按需 |
| **列表更新** | 单条 insert/patch/delete，避免整表重绘 | 父 state 变更易全量 reconcile | §5 P0 memo + 稳定 props |
| **在线状态** | 长连接推送 delta；面板不可见时停刷 | 侧栏 3s 轮询 | §5 P1 可见性门控 + 降频 |
| **已读** | 按 seq/msgId **增量**上报，批量 debounce | 依赖整份 `messages` 扫描 | §5 P1 增量已读 |
| **引用预览** | 存 preview 字段或会话级缓存 Map | render 内 `resolveReplyQuote` | §5 P0 预计算 Map |
| **富文本/代码** | 懒加载、缩略、Worker/后台高亮 | 每条即时 `Markdown`/`hljs` | §5 P0′ 视口内才渲染 |
| **内存** | 历史在本地 DB，内存只保留窗口 | `messagesByGroup` 持续 merge | §5 P0′ 窗口 + 切群降级 |
| **DM 列表** | 会话列表只显示 preview，不预载全历史 | `DmSessionBar` 订阅全表 + 批量 `loadMessages` | §5 P1 轻量 preview |
| **排序写入** | 按 seq 追加 O(1)，乱序才重排 | 每次 upsert 全量 `sort` | §5 P1 Store 增量 |
| **插件 IPC** | 按场景注册一次，启用变更单点刷新 | N×全量 `listMenus` + 惊群 | §5 P0 + §5 P1 序 10 |

**可抄的三条原则**（写进 Code Review 自检）：

1. **配置一次，交互带 id** — 菜单、插件、权限不在列表 item 里重复初始化。  
2. **看得见才算账** — 虚拟列表 + 视口内才做重活（高亮、Markdown、大图）。  
3. **增量同步** — 已读、在线、新消息都尽量 delta，避免 O(N) 扫全表。  
4. **写入便宜** — 追加消息不重排全表；订阅 store 时粒度到 `groupId`，不订整表。

### 9.1 Electron 客户端额外注意

| 项 | 说明 |
|----|------|
| **主进程 vs 渲染进程** | 聊天热点在 Renderer；Performance 录的是渲染线程，P2P 心跳在主进程另看任务管理器 |
| **生产包基准** | `npm run dev` + HMR 会抬高 CPU；性能验收用 **packaged build** 或 `npm run build` 后启动 |
| **DevTools 开销** | 开着 Memory/Performance 面板本身占内存；抽检完关闭 |
| **多窗口** | 若未来多窗口共享 store，需避免每窗重复 `listMenus`（单例应进程级） |

### 10.3 PR / 功能自检（聊天相关）

新增或改动聊天 UI 时，作者自检：

- [ ] 未在 `MessageBubble`（或列表 item）内新增 `usePluginMenus` / `useSlotPlugins` / 每 item IPC  
- [ ] 未在列表 item 内新增 `useNavigate` / `useParams`（路由钩子应在上层）  
- [ ] 列表 item 已 `memo`，回调 `useCallback`，避免 inline 箭头传入

- [ ] 重计算（高亮、Markdown、引用解析）有缓存或仅在视口内执行  
- [ ] 长跑结构（Set/Map）有上限或按群清理  
- [ ] Store 更新避免不必要的全表 `sort` / 全表新数组（追加走 O(1) 路径）  
- [ ] 订阅 Zustand 时粒度到当前 `groupId`，避免 `messagesByGroup` 整表订阅
