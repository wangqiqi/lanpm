# LanPM UI/UX 设计审查报告

> **已归档**（2026-05-29）。**唯一任务真源**：[../todo.md](../todo.md)。审查记录；任务只维护在 todo（§UI/UX — UX-F / UX-I / UX-A / UX-V / UX-R / UX-N）。

> **评估日期**：2026-05-29  
> **评估范围**：`src/renderer` 渲染层（布局、路由、五大视图、Setup、驾驶舱、i18n、主题）  
> **评估方式**：静态代码审查 + 设计令牌 / 组件结构分析（未做可用性测试与用户访谈）  
> **产品定位**：Electron 桌面客户端，Apple HIG 风格 + Ant Design，**非移动端优先**

---

## 1. 设计体系概览

| 维度 | 现状 | 评价 |
|------|------|------|
| 视觉语言 | `--lanpm-*` CSS 变量（亮/暗）、圆角 10–12px、毛玻璃顶栏/底栏 | 统一、现代，品牌感清晰 |
| 组件库 | Ant Design 5 + 自研 `ViewHeader` / `ViewToolbar` / `ViewState` | 任务类视图壳层复用良好 |
| 主题 | `uiStore` + `ThemeProvider` 联动 Ant token 与 CSS 变量 | 亮暗切换完整 |
| 国际化 | 232 个强类型 `MessageKey`，中英 locale 键对齐 | 框架成熟，但存在多处漏网 |
| 导航 | TopBar（群切换/搜索/设置）+ BottomNav（5 Tab）+ Hash 路由 | 结构清晰，符合桌面协作工具习惯 |

---

## 2. 做得好的地方（保留）

1. **群类型驱动 Tab 禁用 + Tooltip 说明**（`BottomNav.tsx` + `tabRules`）— 职能群/匿名群能力边界表达清楚。  
2. **Setup 向导** — 居中 sheet、头像随机/上传、设备名自动检测，首次体验完整。  
3. **聊天 Composer** — 可拖拽高度、`Ctrl/Cmd+Enter` 发送、`/task` 快捷指令、@ 提及、DM 会话栏。  
4. **看板拖拽** — `@dnd-kit` + 拖入 OTHER 列弹原因、列高亮反馈。  
5. **视图级加载/空态** — Tree / Gantt / Chat 等使用 `ViewLoadingCenter` / `ViewEmptyHint`。  
6. **错误反馈** — 多数写操作有 `message.success/error`（看板、甘特、Setup 等）。

### 3.1 功能与交互（P0–P1）

| ID | 严重 | 问题 | 位置 | 影响 | 建议 |
|----|------|------|------|------|------|
| F-01 | **P0** | **全局搜索结果跳转后无高亮** | `GlobalSearch.tsx` 写入 `location.state.highlightTaskId` / `highlightMsgId`；**无任何视图读取** | 用户搜索任务/消息后无法定位目标，搜索体验半成品 | Chat / Board / Tree 消费 `useLocation().state` 并 scrollIntoView + 临时高亮样式 |
| F-02 | **P1** | 他人消息展示 **原始 `senderUserId`** 而非昵称 | `MessageBubble.tsx` L38 | 聊天可读性差，像调试界面 | 用 `members` 映射 `displayName`，fallback 截断 ID |
| F-03 | **P1** | **驾驶舱加载失败后仍渲染全 0 指标** | `CockpitView.tsx` L53–55 catch 后 `dashboard` 仍为 null，L98+ 用 `?? 0` | 用户误以为「没有项目」而非「加载失败」 | 增加 `loadError` 状态：错误页 + 重试按钮，勿展示假数据 |
| F-04 | **P1** | **App 启动身份拉取失败静默** | `App.tsx` L37–41 catch 仅 `setHydrated(true)` | 可能进入主界面但身份/群列表不可用，无说明 | 展示错误页或重试；区分「未配置」与「服务不可用」 |
| F-05 | **P1** | **全局搜索失败静默** | `GlobalSearch.tsx` L64–65 catch 只 `setOptions([])` | 与「无结果」无法区分 | `message.error` 或 AutoComplete 错误态 |
| F-06 | **P1** | TopBar **「个人设置」菜单项永久 disabled** | `TopBar.tsx` L83 | 入口存在但不可用，降低信任感 | 实现或移除菜单项，避免幽灵功能 |
| F-07 | **P2** | **ChatView 与 MemberList 重复请求成员列表** | `ChatView.tsx` L82–85；`MemberList.tsx` L36–46 | 多余 IPC、Sidebar 与 Mention 数据可能短暂不一致 | 成员列表提升到 store 或 ChatView 向下传递 |
| F-08 | **P2** | 聊天 **仅 Ctrl/Cmd+Enter 发送**，Enter 换行 | `ChatView.tsx` L206–210 | 与微信/Slack 等习惯不同，新用户易困惑 | 设置项：Enter 发送 / Shift+Enter 换行；或输入区提示更醒目 |

| F-10 | **P2** | 看板 **无整体空态**（四列皆空时仍显示空列） | `BoardView.tsx` | 新项目首次进入看板缺少引导 | `boardTasks.length === 0` 时显示 `ViewEmptyHint` + 创建任务 CTA |
| F-11 | **P2** | 看板列内 **无「拖放任务到此」占位** | `KanbanColumn` | 空列视觉空洞，拖拽目标不明确 | 列底 dashed 占位 + i18n 文案 |

| F-13 | **P2** | 文件列表 **空态依赖 Ant Table 默认**（英文 "No data"） | `FilesView.tsx` | 与 i18n 体系不一致 | `locale.emptyText: t('files.empty')` |

| F-15 | **P2** | 默认路由写死 **`demo-project`** | `paths.ts` / `AppRouter.tsx` | 无 demo 群时重定向到无效 ID | 重定向到 `activeGroupId` 或第一个真实群 |

### 3.5 布局与响应式（P5）

| ID | 问题 | 说明 |
|----|------|------|
| R-01 | **全 renderer 无 `@media` 查询** | 明确桌面优先；小窗口体验未优化 |
| R-02 | TopBar 控件多（群 Select + 创建 + 驾驶舱 + 搜索 + 主题 + 语言 + 用户），**窄窗可能挤压/溢出** | `TopBar.module.css` 无 flex-wrap / 折叠菜单 |
| R-03 | 聊天侧栏 **固定 240px**（min 200px） | 宽度 < ~900px 时主聊天区过窄 |
| R-04 | 看板 **4 列 × min-width 280px** | 仅横向滚动，无「单列/stack」模式 |
| R-05 | 文件视图 **预览区固定约 36%** | 小屏双栏同时可读性差 |
| R-06 | `100dvh` + `safe-area-inset-bottom` 已用于 BottomNav | 良好；但无窄屏 Tab 文字隐藏（仅 icon 模式） |

**结论**：作为 Electron 桌面客户端可接受；若需 1280 以下或平板，需专门断点设计。

## 6. 审查结论

LanPM 渲染层 **视觉体系统一、桌面导航清晰、核心协作流程（聊天/看板/甘特/文件/Setup）骨架完整**。当前 UI/UX 短板集中在：

1. **半成品能力**：全局搜索跳转无高亮（F-01）  
2. **错误与空态**：驾驶舱/App/搜索失败时用户得不到正确反馈（F-03–F-05）  
3. **i18n 漏网**：看板/优先级/部分气泡仍硬编码（I-01–I-03）  
4. **聊天可读性**：senderUserId、时间格式、送达 emoji（F-02、F-09、I-04）  
5. **无障碍与键盘**：无 focus 样式、@ 无键盘、拖拽仅鼠标（A-03–A-06）  

以上问题均已写入本文件，可按 §5 优先级排期修复。
