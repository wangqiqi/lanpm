## 2. 数据模型（与代码对齐）

权威 TypeScript 定义：`src/shared/task/types.ts`（与 [04 §3.4](./04_数据模型与协议草案.md) 一致）。

| 存储字段 `status` | 看板列 UI 文案 | 常量 |
|-------------------|----------------|------|
| `todo` | TODO | `KANBAN_COLUMN_LABELS` |
| `doing` | IN PROGRESS | |
| `done` | DONE | |
| `other` | OTHER | |

列顺序：`KANBAN_COLUMN_ORDER` = `todo → doing → done → other`（`src/shared/task/kanban.ts`）。

**看板 vs 任务树展示规则**

- **看板**（`BoardView`）：仅展示 **无 `parentTaskId` 的根任务**；子任务只在任务树中维护。
- **任务树**（`TaskTreeView`）：展示完整父子层级；选中叶子节点可编辑 `progressPercent`。

**父任务进度**（`src/shared/task/progress.ts`）：

```text
parent.progressPercent = round( avg( children.progressPercent ) )
```

- 在 `listGroupTasks` 返回前通过 `applyAggregatedProgress` 注入，**不反写 SQLite**。
- 子任务全 `done` 时 **不自动** 提升父任务 `status`（P0 仅聚合百分比，见 04 §3.4）。

**OTHER 校验**（`src/shared/task/validation.ts`）：

- `status === 'other'` 时 `otherReason` 去空白后非空，否则抛出/表单拦截：`移入 OTHER 列必须填写原因`。

## 3. 架构与数据流

```text
┌──────────────── Renderer ────────────────────────────────────────┐
│  ChatView (/task)   BoardView (dnd-kit)   TaskTreeView (Tree)    │
│       │                  │                      │                 │
│       └──────── taskStore (Zustand) ──────────┘                 │
│                         │ getLanpmApi().task.*                  │
└─────────────────────────┼────────────────────────────────────────┘
                          │ IPC (preload)
┌─────────────────────────┼────────────────────────────────────────┐
│  Main: taskService ─────┘                                        │
│    ├─ taskRepository → SQLite tasks                              │
│    ├─ createTaskFromChat → publishChatMessage (task_ref)           │
│    └─ broadcastTasksChanged → TASK_PUSH_CHANNEL 'task:changed'   │
└──────────────────────────────────────────────────────────────────┘
```

### 3.1 IPC 与推送

| 通道 | 方向 | 说明 |
|------|------|------|
| `task:listTasks` | invoke | 按 `groupId` 列表（含聚合进度） |
| `task:createTask` | invoke | `CreateTaskInput` |
| `task:updateTask` | invoke | `UpdateTaskInput` |
| `task:moveTask` | invoke | 改列 + `sortOrder` + OTHER 原因 |
| `task:createFromChat` | invoke | 建任务 + 发 `task_ref` 消息 |
| `task:changed` | push | 参数 `groupId`，渲染层 `onTasksChanged` 刷新 |

定义：`src/shared/task/channels.ts` · 注册：`src/main/ipc/task.ts` · 暴露：`src/preload/index.ts` · 类型：`src/shared/lanpm-api.ts`。

### 3.2 持久化

- DDL：`src/main/storage/schema.sql` → `tasks`、`task_dependencies`（依赖边 M4 使用）
- 仓储：`src/main/storage/repositories/taskRepository.ts`
- 业务：`src/main/task/taskService.ts`

`taskId` 生成：`task_${uuid}`（与 04 §2.1 前缀约定一致）。

### 3.3 渲染层模块

| 模块 | 路径 | 职责 |
|------|------|------|
| 看板 | `src/renderer/src/features/board/BoardView.tsx` | 四列 Droppable、卡片 Draggable、`OtherReasonModal` |
| 看板卡片 | `.../board/KanbanCard.tsx` | 标题、优先级 Tag、进度、OTHER 原因展示 |
| 任务树 | `.../tree/TaskTreeView.tsx` | 根/子任务创建、Tree 展开、叶子进度编辑 |
| 状态 | `src/renderer/src/stores/taskStore.ts` | 按群缓存、`loadTasks` / CRUD |
| 壳路由 | `src/renderer/src/views/GroupView.tsx` | `view=board|tree` 挂载上述组件 |
| 聊天闭环 | `ChatView` + `TaskCreateModal` + `MessageBubble` | `/task`、`task_ref` 跳转看板 |

样式：`board.module.css`、`tree.module.css`（CSS Modules）。

## 4. 交互行为（产品 ↔ 实现）

### 4.1 看板

1. 工具栏「新建任务」→ 弹窗输入标题、优先级 → `createTask`（默认 `status=todo`）。
2. 拖拽卡片至列 Droppable（`id` = `TaskStatus`）→ `moveTask`。
3. 拖入 **OTHER** → 先弹出 `OtherReasonModal`，确认后带 `otherReason` 调用 `moveTask`。
4. 拖拽中：卡片 `opacity: 0.5`；`DragOverlay` 显示标题浮层。
5. 列最小宽度 280px，横向滚动（见 `board.module.css`）。

### 4.2 任务树

1. 输入根任务标题 +「根任务」→ `createTask`（无 `parentTaskId`）。
2. 选中节点后输入子任务 +「添加子任务」→ `createTask({ parentTaskId })`。
3. `Tree` `expandedKeys` 本地 state；`showLine`。
4. 选中**叶子**节点可改 `progressPercent` 并保存 → `updateTask`；父节点进度刷新为子任务均值。

### 4.3 聊天 `/task`

| 输入 | 行为 |
|------|------|
| `/task`（无标题） | 打开 `TaskCreateModal` |
| `/task 修复登录` | `createFromChat`：SQLite 插入任务 + 聊天 `task_ref` |
| 工具栏「任务」按钮 | 同弹窗（仅 `taskAllowed` 群显示） |

解析：`src/shared/chat/taskCommand.ts` · `parseTaskCommand`。

`task_ref` 气泡：点击跳转 `#/g/:groupId/board`（`MessageBubble`）。

## 6. 与 M4 甘特图的衔接

- M4 应 **复用** `taskService` / `taskStore` / `Task` 类型，为已有任务补充 `startDate`、`endDate`、`task_dependencies`。
- 甘特只展示有时间范围的根任务或全部任务（产品待定）；看板仍建议只显示根任务，避免子任务卡片泛滥。
- 读列表时继续调用 `applyAggregatedProgress`，保证三视图进度一致。

## 7. 已知限制（文档化，避免验收争议）

1. **任务未走 P2P 同步**：仅本机 SQLite；多实例任务互不可见，直至 `task_patch` / Yjs（M6 前）。
2. **看板不含子任务卡片**：子任务仅在任务树维护。
3. **列内拖拽排序**：跨列会更新 `sortOrder`；同列内精细排序未单独做 Sortable（可 P1）。
4. **软删除**：仓储有 `softDeleteTask`，UI 未暴露删除入口（验收「删」可后续补）。
5. **assignee**：模型与卡片展示支持，创建弹窗未做成员下拉（可 P1）。
